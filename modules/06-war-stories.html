Module 6

The behavioural round, with receipts

“Tell me about a hard bug” is a test of how you think, not what broke. Each story below has the same shape: symptom, wrong hypothesis, what proved it, what changed permanently.

The shape of a good answer

S
Symptom — what a user or a graph actually showed. Not the cause; you did not know it yet.
H
Hypothesis you rejected — this is the part that signals seniority. Anyone can narrate a fix; naming what you ruled out and how shows method.
E
Evidence — the specific observation that settled it. A log line, a metric, a byte count.
C
Change that outlives the fix — the test, the alert, the rule. A story that ends at “then I fixed it” ends one beat early.

Story 1 — “every test passed and the feature did nothing”

THE INCIDENT 
// Distributed tracing shipped. Six tests, all green.
// Jaeger showed nothing at all.

// The SDK guard was keyed on process.env — which is
// INHERITED at spawn. tsx respawns into a child, so the
// parent started the SDK and the child — where the app
// actually runs — skipped it.
HOW TO TELL IT

Symptom: “Tracing was merged, tests green, and Jaeger had no spans.”

Rejected: “I assumed a collector or sampling misconfiguration and spent time there. Wrong — the SDK was never running in the process that mattered.”

Evidence: “The acceptance check we were using — ‘the SDK logs exactly once’ — was the signature of the bug. It logged once because only the parent ran it.”

Change: “Every test in that area now has to fail when the wiring is removed. Six plan-supplied tests would have passed against a broken implementation; that rule is what surfaced them.”

Five more, compressed

🧊
“Works locally, frozen in production.” A live stream advanced perfectly in dev and never moved behind nginx. Cause: proxy_buffering is on by default — sensible for a page, fatal for a stream. Lesson to state: the packaged shape has failure modes the dev shape cannot have, so it needs its own acceptance run.
📦
“Correct code, 404 in production.” A new endpoint worked in tests and 404’d through the gateway. The running container predated the route. Lesson: first question in any works-here-not-there bug is whether the running artifact contains the change.
🎲
“A flaky test that was not flaky.” Two browser walks failed intermittently and always at the same click. Not randomness — they were racing an asynchronous read-model projection, and a correct 422 came back. Lesson: intermittent plus always-the-same-place means a race, and a race has a signal you can wait on instead of a sleep.
🗑️
“A recovery tool that destroyed data.” The dead-letter replay used a no-ack read: a crash between reading and republishing destroyed the only copy of a message that could not be regenerated. Fixed to ack only after the publish confirms. Lesson: recovery paths need the same durability review as the write path — they run precisely when things are already broken.
🤫
“CI was green and doing nothing.” A shell loop used if ! case … esac; then, and POSIX suspends errexit inside a condition context — so a failed migration no longer aborted the job. Lesson: `set -e` is not a guarantee; verify by making a step fail on purpose and watching the pipeline go red.
🧵
The thread through all six

Every one was found by running the system — in a browser, in the packaged build, against real infrastructure — and every one had a green test suite over it. If you take a single sentence into an interview from this course, take that one.

“How do you know it works?”

The question that separates people who shipped from people who coded. Four layers, each answering a different question.

📊

SLOs with real numbers

Saga p99 < 5s, HTTP p95 < 500ms — expressed as k6 thresholds, so a load run exits non-zero when the objective is missed.

🔥

Burn-rate alerts

Alert on the burn rate of error budget consumption, not on raw error count — which is what stops a 3am page for a one-minute blip.

💣

Chaos scenarios

Kill a broker, kill a service, publish a poison message — then assert the system converges and the right alert fires.

✅

Invariant checker

Six properties across seven databases and both brokers — no order stuck non-terminal, no unsent outbox row, no reservation both consumed and released. Exit code, not a dashboard.

💡
The finding worth quoting

“Latency alerts do not catch hard outages. An open circuit answers in single-digit milliseconds, so during a chaos run availability collapsed while the latency alert never fired. Availability and latency need separate alerts — I found that by breaking the system on purpose, not by reasoning about it.”

“Tell me about the hardest bug you have debugged.” What must the answer contain?

Your tests pass against a broken implementation because the stub was written to match your assumption. What is the systemic fix?

Why is a latency alert insufficient on its own?

The vocabulary sheet

Use these words precisely. Precision is most of what “senior” sounds like.

saga · compensating action Local steps with inverses, standing in for a transaction that cannot exist. Not “rollback”.
choreography vs orchestration React to events vs be told what to do. This system: choreographed execution, centralised state machine.
dual-write problem · transactional outbox Two systems, one commit needed. Turns atomicity into delivery.
at-least-once · idempotent consumer The realistic delivery guarantee, and the property that makes it safe. Exactly-once effects, not delivery.
TOCTOU · compare-and-set · SELECT FOR UPDATE The race, the optimistic fix, the pessimistic fix.
READ COMMITTED Postgres’s default, and the reason two readers can both see a stale row.
refresh rotation · reuse detection · family Rotate, detect replay of a rotated token, revoke one chain rather than one user.
JWKS · kid Publish public keys, select by key id, rotate without redeploying verifiers.
circuit breaker · back-pressure · DLQ Stop calling the dead, limit what you accept, park what you cannot process.
SLO · error budget · burn rate The target, the allowance, and the speed you are spending it — alert on the third.
read model · projection · eventual consistency A local copy fed by events, and the gap you must design around rather than wish away.
🎓
Final rehearsal

Pick any three terms above and explain each in two sentences: what it is, and what it costs. If the second sentence is hard, that is the topic to revisit — an interviewer will find it before you do.
