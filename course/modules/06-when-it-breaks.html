Module 6

Five real bugs, and what they all had in common

These are not invented examples. Each one happened in this repository, and every single one passed the tests.

A green test suite is not evidence

Tests check what someone thought to check. These five bugs each lived in the gap between “the code is correct” and “the thing actually works when a person uses it.”

🌑
The app shipped permanently dark. A styling rule nested inside a “if the user prefers dark mode” block was silently moved to the top by the build tool, so the dark colours overwrote the light ones for everybody. Every test passed — no test looks at colour.
📄
Refreshing a product page returned raw data instead of the page. The web address for the product page and the address for the product data were the same, and the data won. Clicking around worked; pressing F5 did not. The test suite only ever clicked.
🕵️
Tracing was completely dead. The check for “is tracing switched on?” was fooled by how the program restarts itself, so the part doing the real work always skipped it. Six tests were written for it. All six passed against a system that recorded nothing.
📦
A new feature 404’d with correct code. The running container had been built before the feature existed. The code was right, the test passed, the running program was six hours old.
🧊
The live tracker froze in production only. The web server in front of the app — a proxy — was collecting the live updates and holding them until the end, which for a live stream is forever. Locally, with no such server in front, everything looked perfect.

Spot the one that freezes the tracker

Real configuration for the web server that sits in front of the app in production. One line is missing, and its absence is what froze the tracker. Click the line that needs a companion.

Which line is incomplete?

1 location /api/ {
2 proxy_pass http://gateway:8000/;
3 proxy_http_version 1.1;
4 proxy_set_header Host $host;
5 }
🔧
The missing line

proxy_buffering off; — by default this server gathers a response and forwards it in chunks, which is sensible for a web page and fatal for a live stream. The fix is one line; finding it took a browser and a production-shaped build.

The bug that could have passed forever

The server labels each live update status. Browsers deliver a labelled message only to a listener asking for that label — the generic “any message” handler never fires.

WHY IT IS WRITTEN DOWN

The comment exists because the wrong version is the obvious one to write.

Had the test been built around the generic handler, every test would have passed against a page that received nothing at all.

So the fix came with a check: swap the label for the generic handler on purpose, and confirm a test turns red. A test that cannot fail is not a test.

The habit worth stealing: break it on purpose

After an AI writes a test for you, delete the line it is supposed to be testing and run it again. If it still passes, the test is decoration. This one habit catches more fake safety than any amount of reading.

A debugging order of operations

1
Is the running thing the thing you wrote? Rebuild and restart before debugging anything. Hours die here.
2
Which side of the door? Rejected before it reaches a service means gateway — identity, permissions, rate limits. Wrong data coming back means the service behind it.
3
Is anything stuck in a queue? A dead-letter queue filling up names the failing step precisely, and orders frozen part-way through tell you which service stopped listening.
4
Does it break only in the packaged build? Then suspect what is different about that shape: the server in front, the built stylesheet, the environment settings — not the logic.

What you can now say out loud

choreography Parts react to announcements; no conductor. The opposite is orchestration.
saga A sequence of local steps, each with an undo-step, standing in for a transaction that cannot exist.
compensating action The undo-step: release the stock, refund the charge.
outbox pattern Write the announcement with the change, mail it out afterwards.
idempotent Doing it twice is the same as doing it once.
compare-and-set Change it only if it still holds the value I read.
circuit breaker Stop calling something that is down; fail fast instead.
dead-letter queue Where unprocessable jobs are parked for a human.
server-sent events One connection the server writes into as things change.
eventual consistency Everyone agrees in a moment — not this instant. Design for the gap.

The one habit

Every serious bug in this project was found by running the thing — in a browser, in the packaged build, against a real database. Not by reading, and not by a green test suite. Build it, then go and use it.
